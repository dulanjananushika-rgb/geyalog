# GeyaLog · Mobile App

Expo SDK 57 + React Native + TypeScript app for Sri Lankan construction contractors. Local source includes Phases 0–6; Phases 3–6 database migrations and security behavior still require a disposable local/staging Supabase verification run before use against production.

## Run locally

Requirements: Node.js 22.13+ and npm. Copy the example environment file (or keep your existing `.env`):

```powershell
Copy-Item .env.example .env
```

Set these values in `.env`:

```dotenv
EXPO_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co
EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
```

The publishable key (or legacy anon key) is designed for client use. **Never add a service-role/secret key to an `EXPO_PUBLIC_` variable or mobile app.** Restart Expo after editing `.env`.

Install dependencies and start Expo:

```powershell
npm install
npx expo install --check
npm run start
```

For a disposable local database and RLS test environment, install/start Docker Desktop, then run:

```powershell
npx supabase start
npm run test:supabase:local
```

Company onboarding and team management require the Phase 2 migration and the invitation Edge Function. See [PHASE_2_COMPANY_MANAGEMENT.md](./PHASE_2_COMPANY_MANAGEMENT.md). Do not apply the Phase 2 migration to the linked production project until its existing schema and migration history have been reconciled.

The local test command checks that the API URL is exactly `http://127.0.0.1:54321`, reads local-only keys from the Supabase CLI without printing them, and uses synthetic users that it cleans up. It never runs against the URL in `.env`.

Use `a` for Android or `i` for iOS when the corresponding simulator/device tooling is available. `npm run web` starts the web preview; web auth tokens use browser storage, while native iOS/Android use SecureStore. A custom development or production build is recommended for stable mobile deep-link testing.

## Supabase dashboard setup

1. In **Authentication → Providers → Email**, enable email/password sign-in and keep email confirmations enabled.
2. In **Authentication → URL Configuration → Redirect URLs**, allow `geyalog://auth/callback` and `geyalog://auth/callback?intent=recovery`.
3. For Expo Go only, add the exact `Linking.createURL('auth/callback')` redirect generated by that Expo Go session. It may change with the development host; use a development build for a stable `geyalog://` scheme.
4. Keep the default confirmation and password-reset templates, or ensure custom templates use `{{ .RedirectTo }}` so the requested app callback is retained.
5. For a disposable local database, apply all files in `supabase/migrations/` in timestamp order (`20261011000100` through `20261011001100`) and run the local integration tests. Do not apply the Phase 3–6 migrations to the linked production project until current remote schema, policies and migration history have been compared and staging verification passes.
6. If using a custom SMTP provider, configure and verify it in Supabase Auth before real email delivery testing. Supabase's default sender has rate and deliverability limits.

The app's `geyalog` scheme is in `app.json`; native app binaries must be rebuilt after changing the scheme or native modules. Supabase project configuration and email delivery are remote setup, not included as credentials in this repository.

## Authentication flow

- Sign-up calls Supabase `auth.signUp` with `full_name` metadata and a PKCE email callback. With confirmation enabled, the account remains outside authenticated routes until the email link has been exchanged for a session.
- The database trigger creates `profiles` in the same transaction as `auth.users`. Existing users are backfilled when the profile migration is applied.
- Sign-in calls `auth.signInWithPassword`; unconfirmed users are routed to verification instructions. Supabase Auth must keep email confirmation enabled for server-side enforcement.
- Verification links exchange the PKCE code, with a token-session fallback for compatible links. Password-reset links exchange a recovery session, then `auth.updateUser({ password })` saves the new password.
- Resend confirmation uses Supabase Auth's resend endpoint and a local 45-second cooldown. Password reset responses use Supabase's generic response to avoid disclosing whether an email has an account.
- Expo Router `Stack.Protected` guards authenticated/public route groups after session restoration. This is navigation control only; Postgres RLS remains the data-access boundary.
- Native auth session storage uses Expo SecureStore. A pre-existing Phase 0 session is moved from AsyncStorage to SecureStore the first time it is restored. Supabase auto-refresh runs only while the native app is active. Web preview uses browser local storage and should not be treated as encrypted native storage.

## Folder structure

```text
app/
  _layout.tsx                    Root providers and Expo Router guards
  index.tsx                      Session-aware route entry
  (auth)/                        Welcome, sign-in/up, verify, password request
  auth/callback.tsx              Confirmation and recovery deep-link handler
  (app)/index.tsx                Temporary authenticated home
  (app)/profile/                 View and edit the user's own profile
  (app)/reset-password.tsx       Recovery-session password update
  (app)/setup.tsx                Existing Phase 0 company setup (preserved)
  (app)/projects/                Existing Phase 0 projects (preserved)
  (app)/workforce/               Worker, attendance, rate, settlement and subcontractor routes
  (app)/materials/               Materials, requisitions, purchase orders and supplier-finance routes
src/
  components/ui.tsx              Shared fields, password visibility, buttons, brand
  i18n/index.ts                  Supported language registry
  lib/auth-errors.ts             Safe Auth error messaging
  lib/auth-validation.ts         Zod sign-in, signup, recovery, and profile schemas
  lib/profile.ts                 RLS-scoped profile read/update operations
  lib/supabase.ts                Env-based client, PKCE, SecureStore adapter
  providers/session-provider.tsx Session restore and recovery state
  theme/tokens.ts                Existing shared visual tokens
supabase/migrations/             Phase 0–6 schema and security migrations
```

`PROJECT_PROGRESS.md` and `PHASE_3_6_STATUS.md` describe implementation and unverified flows. `ARCHITECTURE.md` documents routes, schema, and security policies. Current Phases 3–6 sources exist locally, but their migrations have not been verified or deployed against the linked Supabase project.

## Checks and known dependency findings

Run `npm run typecheck`, `npm run lint`, and `npm test`. The current app build was exported for web and Android. Expo's SDK compatibility check uses the local SDK dependency map when its network endpoint is unavailable. The dependency install reports inherited upstream npm audit findings in Expo/Metro and tooling dependencies; review `npm audit` before a production release and avoid forced major-version downgrades.
